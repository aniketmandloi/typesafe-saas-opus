# Better Auth is an identity store, not a domain layer

Better Auth is the canonical record of who a user is, which sessions exist, and who belongs to which Organization. It is not where domain behaviour lives. Every domain mutation runs through the kit's own use cases against Better Auth's tables, its org-mutating routes stay fenced off the public surface, and **the `@repo/auth*` packages are the only ones permitted to touch the Better Auth API**.

Auth is consequently the one infrastructure capability with **no Adapter**, in a kit that seams storage, email, queue and billing. That will read as an oversight to anyone who has seen [ADR-0004](./0004-adapter-seam-demand-shaped-and-statically-composed.md); it is a decision.

The kit is maximally coupled here on purpose. [Tenancy model and data isolation](https://github.com/aniketmandloi/typesafe-saas-opus/issues/3) made Better Auth's `organization`, `member` and `invitation` tables canonical, with the kit's own tenant tables holding foreign keys into them, because a mirrored org table would be exactly the second hand-maintained declaration the kit's typesafety contract forbids. That decision stands, re-examined rather than inherited — and what makes it survivable is that **those are ordinary Postgres tables in our own database**. In every scenario where Better Auth becomes unusable, the data is untouched and the DDL is unchanged; what is lost is code, not schema. The dependency is on a generator and a migration path, not on a living upstream.

## Considered options

**An auth Adapter** is the shape every other capability takes, and its precondition contradicts a locked decision. An interface hiding `organization`/`member`/`invitation` behind kit-owned types is a mirror declaration — the thing [#3](https://github.com/aniketmandloi/typesafe-saas-opus/issues/3) refused to build. [ADR-0004](./0004-adapter-seam-demand-shaped-and-statically-composed.md) permits a one-implementation seam only where it buys containment, as billing's does by keeping merchant-of-record concepts out of use cases. There is nothing to contain here and nothing to substitute, so the seam would be theatre: ceremony around calls that still go to one library, paid for on every read of the code.

Containment is bought instead by the fence, which is a policy rather than an interface. [ADR-0007](./0007-organization-soft-delete-and-purge.md) fenced Better Auth's member-mutating routes to protect the last-owner rule and the Dark rule; [ADR-0008](./0008-audit-events-written-by-use-cases.md) extended it to every org-mutating route so audit writes land in our own transaction. Both were forced by defects rather than chosen. This ADR states the general rule those two discovered locally and under duress, and the rule is what bounds the exposure: a diffuse "we are maximally coupled" becomes a small, enumerable, testable call list living in one package.

**Vendoring or forking now** was rejected as premature. MIT is irrevocable for released code, and Vercel's acquisition (announced 2026-07-07) reaffirmed MIT, the name, the team and framework-agnosticism; releases continue to ship. Forking a live dependency to hedge a risk that has not materialised buys nothing and is paid for at every upgrade. Exact version pins plus the two gates below are the mitigation; the fork trigger is written down instead of exercised.

## Consequences

**That rule names two packages, not one, and the slice is what forced it.** The Better Auth server instance pulls the server SDK and the Drizzle adapter, so its package is `server`-tagged; the browser and Expo clients need `better-auth/client` and `@better-auth/expo`, which pull neither. A platform tag is one bit per package and never per subpath ([#2](https://github.com/aniketmandloi/typesafe-saas-opus/issues/2)), so a single `universal` `@repo/auth` would ship the server SDK to mobile and make that bit a lie. The seam is therefore **`@repo/auth` (`server`) and `@repo/auth-client` (`universal`)**, with the client importing `type { auth }` from the server package **type-only** — the same carve-out [#2](https://github.com/aniketmandloi/typesafe-saas-opus/issues/2) already makes for the `AppRouter` import, and erased before any bundler sees it. This widens the fence by one package and changes nothing about why it exists: the mitigation is that the call list stays **enumerable**, and two named packages are as enumerable as one. It is also where [better-auth#10545](https://github.com/better-auth/better-auth/issues/10545)'s workaround lives — the post-sign-in `refetch()` React Native still needs under 1.7.5 is a Better Auth API call, so it belongs at a sanctioned call site rather than in a screen.

**Two risks remain live, and they are not the ones usually named.** A licence change is effectively dead and archival is remote. What is real is, first, **maintenance drift on the org and enterprise surface** — [ADR-0008](./0008-audit-events-written-by-use-cases.md)'s defect list is evidence that surface was already under-invested before the acquisition, and post-acquisition engineering energy points at agent identity on Vercel's product surface, which is not where this kit's dependency sits. Second, **Vercel-shaped feature gravity**: capability arriving that assumes Vercel primitives, in a kit where AWS is a proven target rather than a documented one.

**The kit adopts only plugins that run identically on containers, Lambda and Vercel**, with no platform-specific service behind them. Agent identity is not adopted in v1 — not rejected on merit, simply not this kit's problem. Adopting such a plugin later is a new decision, never a version bump, because it would silently demote AWS from proven. The kit already refuses to let an auth implementation detail choose its targets: Better Auth's pure-JS scrypt exceeding the Workers CPU limit was one of the costs that ruled Workers out ([ADR-0002](./0002-cloudflare-workers-is-not-a-target.md)).

**An upgrade passes two gates, both mechanical.** ~~`auth generate` must be a no-op against the committed schema~~ — **replaced by [ADR-0011](./0011-kit-owns-the-auth-schema-declaration.md)**, which makes the Drizzle declaration the kit's own file, so there is no generated output to assert against; the first gate is now an awaited `checkSchema()`, plus a behavioural smoke test for the drift it cannot see. And a test enumerates the **mounted route set against an explicit allowlist**, failing on any route the allowlist does not name. The second gate is what makes the fence hold through upgrades rather than through memory: a new org-mutating route in a minor version would otherwise mount silently, which is precisely the drift risk's shape. Undoing that test reopens it with no other symptom.

**The fork trigger is a kit-operator decision, written here rather than in cloner-facing docs.** A forked project vendors Better Auth when a needed fix sits unmerged for long enough to hurt, when a breaking change lands on the org schema with no migration path, or on any licence change to a version worth taking. The procedure is `pnpm patch` first and a vendored package second. This is cheap specifically because the kit is private fork-and-go under MIT and already consumes packages as TypeScript source, with no build step to reproduce.

**The cost of the coupling, written down once.** If Better Auth became unusable the kit would own: password hashing, sessions and revocation, OAuth providers, email verification and reset flows, and the `organization`/`member`/`invitation` routes — weeks of work, unpleasant but bounded. The expensive half is **SAML and OIDC SSO, SCIM provisioning, passkeys, TOTP, and the impersonation plugin [ADR-0005](./0005-admin-app-reads-metadata-not-content.md) structurally depends on**, which is the part the commercial alternatives charge enterprise rates for. That list, not the table coupling, is the real price — and it is a price paid for capability received, not an accident.
